<h1 align="center">今天麦什么 · mcd-fortune-order</h1>
<p align="center"><strong>把「随便吃点」变成「就吃这份」。</strong></p>
<p align="center">一只薯条签筒，一份符合心情的搭配，一顿自己决定的麦麦。</p>

你也有这样的时刻吗？打开菜单，看了半天，还是不知道今天吃什么。

**今天麦什么**把选择过程做成一个小小的抽签舞台：选好今天的心情和不想吃的东西，摇出一份搭配。喜欢就加入待购清单，不喜欢就换个口味。

当前提供两个入口：**浏览器演示**使用明确标注的历史样例，体验抽签和模拟购物车；**本机 MCP 入口**使用自己的 Token，实际查询龙腾大道店、读取支持套餐的默认配置、核价后抽签。两者还未连接成完整的在线点餐网站。

面向手机和电脑浏览器，适合午餐选择困难、想换换口味，或只是想给这一餐增加一点仪式感的人。

> **当前进度 · 2026-10-09**  
> **开发预览版**：包含128条签文、浏览器演示，以及可运行的只读 MCP 命令行入口。已完成构建、42项单元/组件测试、6项MCP合同测试；真实客户端已成功查询营养表与门店状态。龙腾大道店在本次23:45验证时已休息，程序正确停止，没有生成虚假可购买推荐。新客户端的完整实时核价仍待营业时验收。真实网页MCP集成、套餐微调、外送与真实下单尚未实现。以下插画布局是设计稿，验证边界见[验证记录](docs/VALIDATION.md)。

## 怎么玩

以下是完整产品的设计流程；当前网页实现其中的到店演示、抽签、换口味、模拟购物车与模拟确认。外送和微调暂未开放。

**① 今天，怎么和麦麦碰头？**

- **出门走走，进店接麦麦**：选好门店，最终按该店实际支持的方式堂食或取餐。
- **原地躺好，等麦麦上门**：选择配送地址，再查询可配送门店和餐品。

**② 今天想吃哪一款心情？**

| 心情 | 这一餐的方向 |
|---|---|
| 🍟 今日放纵餐 | 来点喜欢的口感，自己决定份量 |
| 🌽 清爽均衡餐 | 按可核实的餐品与营养资料比较搭配 |
| 🍦 来点小确幸 | 给自己安排一份小食或甜品 |

不问预算。可以补充「不吃辣」「不想吃牛肉」「不想吃鱼」「不想喝咖啡」「不想喝含糖饮料」等偏好；不确定的餐品属性不会被当成已经满足条件。

**③ 摇一签，看看今天麦什么**

薯条签筒轻轻摇动，一张签揭晓今天的搭配。大吉有金色闪光，小吉也有暖暖的陪伴：

> **小吉 · 慢慢来也很好**  
> 今天先照顾好自己，别的事一件件来。

所有等级都可以推荐完整的餐点。签的等级不决定份量、价格和优惠资格；签文是娱乐性的用餐文案，不预测现实运势。

**④ 这一餐，你说了算**

- **就吃这份**：确认餐品、规格和数量，加入本应用购物车。
- **换个口味**：保留条件再摇一次，已有购物车不变。
- **微调一下（计划中）**：在门店允许的范围内换配餐或饮料，重新核价。

演示版可以修改待购数量并进行模拟确认，不创建任何真实订单。正式交易流程计划在重新核价并由本人确认后才创建订单，再前往官方返回的支付入口。

## 从真实菜单，到真实选择

我们已用 **麦当劳上海龙腾大道餐厅**完成首轮只读验证：

| 2026-10-09 的历史报价示例 | 当次金额 | 说明 |
|---|---:|---|
| 巨无霸＋中薯条＋可乐中杯 | ¥37.50 | 该次核价未使用指定优惠券 |
| 汉堡包＋麦乐鸡4块＋苹果片60g＋无糖可乐中杯 | ¥28.00 | “堡”你欢乐套餐；营养总量尚未逐项核验 |
| 巨无霸＋小杯玉米杯＋无糖可乐中杯 | ¥36.50 | 替换后的套餐配置已核价 |
| 草莓麦旋风1份 | ¥9.90 | 仅为当次账户已有券报价，非人人可享价格 |

这些是历史验证记录，不是今日价格承诺。实际使用时重新查询门店、库存、配置、券条件与金额；券和营养资料不会被包装成无条件优惠或健康保证。

本机 MCP 入口目前负责：

1. 找到上海龙腾大道门店，检查营业状态。
2. 查询菜单，只对两种受支持且当前可见的套餐读取默认配置。
3. 按完整默认配置核价，再独立抽取娱乐签文。
4. 门店休息、配置不完整或核价失败时停止，不用历史报价补位。

该入口不使用账户优惠券、不处理营养偏好、不建单；默认套餐价格不等于最低价。优惠、偏好和交易的完整集成仍在开发。

购物车由本应用维护；目前没有独立的官方购物车 MCP 工具，不承诺同步至麦当劳 App 或小程序购物车。工具、数据格式和验证范围见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md)。

## 体验与安装

需要 Node.js 22或更新的受支持版本。当前为开发预览，可本地构建运行；在线演示发布状态以本仓库 About 中实际链接为准。

安装依赖后已执行通过构建与单元测试。锁文件已生成，新环境可使用以下命令；完整的干净环境复现仍需记录：

```powershell
npm ci
npm run build
npm test
npm run preview
```

在本地PowerShell中运行，按终端输出打开本机预览地址。网页只使用演示数据，不接收真实Token或创建真实订单。

### 真实 MCP 查询

在自己的本机终端配置 `MCD_MCP_TOKEN`。PowerShell 7可用下面的掩码输入，不把Token写到命令历史或文件中：

```powershell
$env:MCD_MCP_TOKEN = Read-Host "输入自己的麦当劳 MCP Token" -MaskInput
npm run mcp:check
npm run mcp:draw
Remove-Item Env:MCD_MCP_TOKEN
```

`mcp:check`实际查询营养表但只打印连接摘要；`mcp:draw`实际查询门店和支持套餐，核价后在终端返回餐品、金额与签文。休息时会返回门店不可用。此入口仅支持龙腾大道店两种指定主餐的当前默认配置，不执行网页偏好筛选、不使用优惠券、不建单。运行 `npm run test:mcp` 可执行不联网的合同测试。

正式版本设计两种模式：

- **演示模式**：无需账户，使用明确标注的示例数据体验选择、抽签、微调和模拟购物车；不创建真实订单。
- **个人本地模式**：使用自己申请的麦当劳 MCP Token，由本地服务端读取，查询自己账户下的真实菜单和优惠。默认只读；订单能力单独开启并要求逐单确认。

公开演示站只提供演示模式，不共享开发者个人 Token。首版不提供公开多用户账户托管。

配置结构见 [mcp-config.example.json](mcp-config.example.json)。示例中的环境变量占位符需要由使用它的客户端或服务端配置层解析；它本身不是已验证的通用启动配置。**不要把真实 Token 写进仓库、前端代码、浏览器存储或截图。**
